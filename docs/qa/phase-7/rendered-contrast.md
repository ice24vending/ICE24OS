# Contraste renderizado: medición y corrección P13

11/11/2026. El reporte histórico contenía **26 análisis** indeterminados, no 26 elementos únicos. El preflight actual tenía **28 análisis / 52 elementos**. Se midieron todos; diez instancias de la lista de acceso fallaban. La repetición añadió una instancia del enlace Archivos: **53/53 cumplen** después de corregir. No acredita prueba humana con lector ni aprobación UX.

## Método y defecto real

Se obtuvieron estilos computados y capturas del producto en Chromium Linux, 375/768/1280. Se capturó el mismo rectángulo antes y después de volver transparente únicamente el texto, sin cambiar geometría ni fondo. Se calculó el mínimo WCAG sobre cada píxel de fondo donde había glifo (diferencia de al menos un nivel RGB), con color/opacity computados; 4,5:1 normal y 3:1 grande. Los iconos de verificación del acceso también se comprueban a 4,5:1 en E2E (más estricto que 3:1).

La inspección individual de capturas detectó texto blanco sobre la parte clara de la diagonal: **1,056:1**. El primer diagnóstico descartaba diferencias inferiores a 30 niveles y lo omitió: se corrigió el método y recalcularon todas las capturas, sin conservar ese falso positivo. Ahora `.brand-panel` usa `--color-surface-brand`, una superficie opaca; se mantienen texto/información y tokens inversos. `AccessBrandPanel` se comparte entre acceso real y Storybook. La demo usa el mismo CSS.
